Digital Forensics & Incident Response (DFIR) Manual

Academic & Industry Standard Incident Handling Architecture

1. Detection Engineering & Velocity Logic

The system deploys a sliding-window rate analysis queue:

  • Human Friction Baseline: 3-4 failures over 180s with typing jitter -> tolerated without lockout.
  • Automated Malware Burst: 5 or more failures in 15s -> classified as critical credential guessing.
  • Containment: User is automatically marked is_locked = True and must_reset_password = True.

2. 3-Password History Cryptographic Policy

When a quarantined employee initiates password remediation:

  • Complexity: Min 8 chars, 1 uppercase, 1 lowercase, 1 number, 1 special symbol.
  • Active Check: Plaintext compared with current salted bcrypt hash.
  • History Check: Salted hash checked against last 3 records in password_history table.
  • If any match is detected, the password reset is rejected with an explanatory security policy error.

3. AI SOC Analyst Architecture

When an incident triggers, the AI Security Analyst engine evaluates forensic metadata:

  • Cadence and velocity time-span calculation.
  • MITRE ATT&CK Matrix mapping (T1110.001, T1190, T1059.007, T1046).
  • Evidence Timeline generation.
  • Actionable SOC Runbook playbooks (Containment, Quarantine, Firewall rules).
